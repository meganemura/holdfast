# Changelog

## Unreleased

First release.

- `holdfast check FILE... [--suspect YAML]...` turns each suspicion (`says`, `given`, `do` or `race`, `pause`, `expect`) into a spec that builds its records with the app's factories, runs it on base and on the working tree, and reports `confirmed` with the kept spec, `refuted` with the observed values, or `could_not_run` with the error and the part of the suspicion it came from. A `race` holds one action at a pause point (`batch_load`, `outside_call`, `row_lock`, `first_write`, or a method) while the other runs, and is confirmed only when that order ends in a state no serial order reaches. With no change, or `--here`, a check runs once on the working tree. An error keeps 300 characters of its first line, enough for a constraint name, and a `do` of several lines is shown on one line.
- `holdfast run` checks a change against its base: one row per changed method and per caller of a changed constant or scope, from the tests that name it, the test files the change edited, evidence under `.holdfast/evidence/`, and pins drafted from the method's parameters. It needs jitcatch and branchout, which are not on RubyGems yet; without them it exits 1 and says how to install them. A test counts by its own example's lines and, for a branch on one line such as `return x if y`, by the arm it took. New behavior that only the change's new specs run is `intended_change`, and a controller action gets no drafted pin, since it needs a request.
- `holdfast run` with nothing changed drafts one sequence definition per write area into `.holdfast/sequences/` and hunts with random orders, interleavings at an outside call or a batch load, other time zones and UTC offsets, and a desk route against an API endpoint, under drafted and written invariants. `--sequences` hunts over the areas a change touches, and `--observe` compares each area's action orders on base and head. The drafted world uses a parent a unique index holds to one child only once, and sets a capacity column only when the record stays valid with it. A rule the drafted setup breaks before any action is reported as unchecked, not as a suspected bug, and the unreached line names each thin area's file and its first unreached actions. Desk forms are drafted from `params.expect`, `params.dig`, and the `*_params` helper an action calls, and a param the action reads as a file is sent as one. Two doors are compared only on the columns both can set, and not at all when one takes an option the other names differently. An error in holdfast's own code is reported as holdfast's, not as a suspected bug in the app. When the time limit cuts shrinking, the failure found first is reported with its sequence and marked not shrunk, instead of `SIGTERM`. The drafted world marks a record settled at the amount its captured payments add up to, so a drafted money rule holds before the first action. A path segment the controller finds by another column (`find_by!(code: params[:location_id])`) is sent that column. A form field is drawn by its column type, a unique column takes a new value from the factory, and a string the model refuses as free text is drawn from the factory's value, free text, and blank. A form shown again with errors is reported by its record's error messages, not the page title. Two doors are not compared when one makes a new unique value the other draws from existing records, or picks a record from a list the other never draws from (the desk picks a member, the API acts for whoever signed in). The setup also makes the records the actions read in the probe, such as a member's membership, gives each factory trait a turn (a host, then a manager), and puts the API caller's own record in the list its children are made from. An API that reads its token through a helper (`bearer_token`) is sent that header. A path param an endpoint finds its record by (`find_by!(number: params[:number])`, `guest_passes.find(params[:id])`) is drawn from that record, and so is a body param a controller finds a record by (`Member.find_by!(email: ...[:host_email])`). A table an action copies a value from is made in the setup even when the area inserts into it. The note at the top says `HUNT REACHED LITTLE` only when an area reached under half its actions, and `hunt:` otherwise.
- Each app gets its own test database names through `DATABASE_URL`, so base, head, and other apps on one server do not share one.
- An agent skill in `skills/holdfast/`.
- Ruby 3.4 or newer. The one runtime dependency is hegeltest 0.4.1.
